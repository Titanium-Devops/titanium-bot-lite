# Audit of 0.1.11, against the port plan

Date: 2026-09-13. Read against `docs/console-pieces.md` (the console port plan), `docs/agent-pieces.md`
(the agent port plan), `SPEC.md` (the delivery order) and `docs/REPORT.md` (steps 1 to 6a).
Everything in the "measured how" column was run on this Mac on this date, against the tree at
`main`, tip `347daba`. Screenshots are in `docs/audit-shots/`.

## How it was measured

- `python3 -m unittest` in a clean worktree: **101 tests, 101 passed, 0 skipped**, exit 0, 26.4 s.
  Every socket test the earlier reports had to skip now runs.
- Lite started for real on a spare port: `TIINY_MODEL=echo python3 -m lite --port 7797
  --bind 127.0.0.1 --data-dir <scratch>`. It printed
  `Budget: {"rssMb": 41.62, "firstPaintKb": 23.49, "coldStartMs": 937.86}` and answered
  `GET /api/health` with `{"app": "titanium-bot-lite", "version": "0.1.11"}`.
- One real chat turn through the documented HTTP API: `POST /api/send` returned the person's row,
  and `GET /api/transcript?agentId=titan` two seconds later held the seeded first-run greeting, the
  message and the reply. The queue, the worker, the transcript writer and the poke all work.
- The console was opened in headless WebKit through playwright-core at 1440x900 and 390x844, the
  door pressed, and the page driven: the Talk button, the phone plus menu, all four Settings
  sections, the Files, Routines and Skills panels, the roster drawer, and a file row.

## What could not be measured, and why

A Tiiny is attached to this Mac over USB. `lite.device.find_base()` found it in 0.9 s at
`http://172.17.7.177/v1`, which is the discovery feature working exactly as `lite/device.py`
describes. **No real device turn was run.** The device answers `401 auth_failed` without a key, and
the only key on this machine is in a file this audit is not permitted to open. So every model
measurement below is the echo model, and nothing here establishes device inference, device speech
to text, device text to speech or model start and stop against real firmware.

## Disposition

Fixed in this pass: rows 1, 2, 3, 4, and the stale version number in the README.

Briefed for a worker, because each is larger than half an hour or cannot be verified from this
machine without the device key: rows 5 and 6 in `docs/STEP-7A.md`, rows 7 and 8 in
`docs/STEP-7B.md`, rows 10 and 11 in `docs/STEP-7C.md`.

Row 9 is folded into `docs/STEP-7C.md` as a sweep rather than fixed here: the desktop sizes are the
shelf's own, and moving them without a rendered before-and-after is how a phone layout regresses.

Row 12 needs nothing.
